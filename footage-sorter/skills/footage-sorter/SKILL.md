# 素材分类（footage-sorter）

把一堆视频素材变成：**一个能筛选的离线目录网页 + 一张表格 + 一个导进 Final Cut Pro 就分好类的关键词资源库**。核心是让 AI 看每条素材的 6 帧缩略图打标签，数字指标（亮度、锐度、画面变化）只做参考。

脚本都在本技能目录的 `scripts/` 下（下面写作 `<技能目录>`，就是这个 SKILL.md 所在的文件夹）。只需要 Python 3.9+、ffmpeg/ffprobe、Pillow；先跑一次 `python3 <技能目录>/scripts/doctor.py`，缺什么按提示让用户装（装东西前先问用户）。

在 Claude Code 和 Codex 里都能用，两边只有两处不同：

| | Claude Code | Codex |
|---|---|---|
| 看联系表图片 | Read 工具 | view_image 工具 |
| 分批派助手 | Agent 工具（general-purpose） | spawn_agent（多代理功能）；没有就自己按批做 |

**Codex 的沙箱**：能写哪里取决于用户的 Codex 设置，常见的默认是只能写当前工作目录。所以在 Codex 里，工作文件夹和输出文件夹默认放在当前工作目录下（`./素材分类-<文件夹名>/`）。用户想放到别处（比如 `~/Movies/`）时，先试着写一下；写不了就告诉用户原因，请他换个工作目录启动 Codex 或放宽权限，不要自己绕过。读原素材一般不受限制。

## 铁律

- **原素材只读**：不移动、不改名、不删除、不转码原文件。所有中间文件放在工作文件夹，成品放在输出文件夹。
- **不凭风景猜地点**：地点只来自用户给的行程、文件夹规则，或画面里直接看得见的线索（招牌、著名建筑）。
- 分类结果要**过检查脚本**、要**抽查**，才能交给用户。

## 第 0 步：问清楚（一次问完，有默认值就别多问）

1. 素材在哪个（些）文件夹？有没有要跳过的子文件夹（备份、别的旅行）？
2. 输出放哪？默认 `~/Movies/素材分类/<文件夹名>/`（Codex 里默认 `./素材分类-<文件夹名>/`，见上面的沙箱说明），工作文件放它下面的 `_工作文件/`。
3. 要剪成什么样的片子？（一句话就行。用来写进说明书的「背景」，必要时改「风格」「用途」两组词。）不说就用默认的旅行/生活词表。
4. 用不用 Final Cut Pro？不用就跳过 FCPXML，只给网页和表格。

## 第 1 步：扫描

```
python3 <技能目录>/scripts/scan.py <素材文件夹> [更多文件夹] --work <工作文件夹> [--exclude 备份]
```

读出每条视频的时长、分辨率、帧率、竖拍、时间码、机型、GPS、拍摄日期和日期来源；0 字节/损坏的标坏文件；同名同大小的副本只留一份。把输出的统计用大白话告诉用户：多少条、总时长、坏文件几个、日期来源分布、每天几条。

**日期**：文件名里的日期（大疆、手机）最可靠；手机文件里的拍摄时间次之；被达芬奇/Premiere/剪映等重新导出过的文件，日期是导出日，脚本会标成不可信、日期留空。

**地点（行程段）**：如果素材跨了好几个地方，请用户给行程（哪几天在哪），写成 `<工作文件夹>/itinerary.json`：

```json
[{"from": "2026-03-01", "to": "2026-03-05", "place": "日本·京都"},
 {"from": "2026-03-06", "to": "2026-03-09", "place": "日本·大阪"},
 {"folder": "富士山航拍", "place": "日本·富士山"}]
```

`folder` 规则（相对素材文件夹的子文件夹名）优先于日期规则，用来给没有日期的素材定地点。用户不给就不分地点，只按日期分。

## 第 2 步：词表（可选）

第一次运行会把默认词表复制到 `<工作文件夹>/vocab.json`。只在用户有明确的成片风格时才改它：改 `project`（背景一句话）、`style`、`role` 的取值。别删 `quality` 里的「竖拍」「无」，别改 `key`。改完再继续。

## 第 3 步：抽帧和联系表

```
python3 <技能目录>/scripts/extract.py --work <工作文件夹> [--batch-size 100]
python3 <技能目录>/scripts/make_brief.py --work <工作文件夹>
```

每条抽 180p 小图（大疆有 .LRF 代理就用代理，快很多），算亮度/锐度/画面变化/色彩度，拼成 6 帧一行、10 条一张的联系表，按每批约 100 条分好批（`batches.json`），再生成给分类助手的说明书 `brief.md`。800 条素材大约 5–15 分钟，主要花在解码 4K 上。可以重复运行，已经做过的会跳过。

## 第 4 步：AI 看图分类

读 `batches.json`。每一批派一个子代理（Claude Code 用 Agent 工具；Codex 用 spawn_agent；能并行就并行，一次最多 8 个），提示词照这个写：

> 你是素材分类助手。先完整读这份说明：`<工作文件夹>/brief.md`。你负责第 {batch} 批，共 {n} 条（{第一个编号}–{最后一个编号}）。用看图工具（Claude Code 的 Read、Codex 的 view_image）逐张看这些联系表：{sheets 列表}。按说明给每条写一行 JSON，写到 `{out}`。写完按说明运行检查脚本直到 OK。只看联系表图片，不要打开或改动原视频，不要改别的文件。最后按说明交回摘要。

**更省的做法（推荐，素材多时尤其）**：不派子代理，直接运行
`python3 <技能目录>/scripts/classify.py --work <工作文件夹> --backend codex --effort medium`（或 `--backend claude`）。它把联系表图片直接交给本机的 `codex exec`（或 `claude -p`），按 `schema.json` 拿回结构化结果并自动检查、失败重试一次；中断后重跑会跳过已分好的。实测 Codex 推理强度「中」：27 条不到 1 分钟、额度几乎不动，标签质量和子代理做法一致。`make_brief.py` 会同时生成它需要的 `brief_exec.md` 和 `schema.json`。**用国产大模型（或任何 OpenAI 兼容的视觉接口）**：`--backend api --api-base <接口地址> --api-model <能看图的模型名>`，API Key 放在环境变量 `FOOTAGE_API_KEY` 里（不要写进命令行或文件，也不要替用户保管）。先跑一次 `classify.py --backend api --api-base … --api-model … --test` 确认连得上、模型能看图。每次请求发 1 张联系表（10 条），3 个并行；模型不支持 JSON 模式时会自动改用普通回答再解析。只能处理文字的模型（如 DeepSeek 的对话模型）做不了。

整条流程（第 1、3、4、5、6 步）也可以一条命令跑完：`python3 <技能目录>/scripts/run_all.py --src <素材文件夹> --out <输出文件夹> --backend codex`（不处理行程表）。

没有子代理可用就自己一批一批做，做法相同：看完一批、写完 `out`、跑过检查，再做下一批（中途断了也不丢已做的）。

**开始分类前先提醒用户时间和额度**（素材多的话先问他要不要只分一部分，比如先跳过某些文件夹）：
- Claude Code：实测 27 条用约 13 万 token、7.8 分钟（每条约 17 秒）。
- Codex（ChatGPT Plus，最高推理强度）：实测 10 条用约 6 分钟，占 5 小时额度的 12%、每周额度的 2%，即 Plus 一周大约只够分 400–500 条。分类不需要最高推理强度，建议提醒用户把推理强度调到 medium（`/model`）。

**换成别的模型**（Claude Code 或 Codex 接第三方模型接口）也能用，但那个模型必须**能看图**，并且会调用工具读写文件；只能处理文字的模型做不了这一步。

## 第 5 步：检查和抽查

```
python3 <技能目录>/scripts/check.py --work <工作文件夹>
python3 <技能目录>/scripts/spotcheck.py --work <工作文件夹>
```

- `check.py` 列出漏掉的编号和不合法的值；有问题就把那一批（或漏掉的编号）重新派出去，直到退出码为 0。
- `spotcheck.py` 每批随机抽 2 条，把标签写在缩略图上，生成 `spotcheck.jpg`。**自己打开看**：标签和画面明显对不上的超过 2 条，就改说明书或重做那一批。告诉用户抽查了几条、对了几条。

## 第 6 步：出成品

```
python3 <技能目录>/scripts/build.py --work <工作文件夹> --out <输出文件夹> --event <FCP 事件名> --title "<网页标题>"
```

输出文件夹里：
- `index.html`：离线目录，浏览器打开，能按地点/场景/用途/评分筛选、搜索，点「播放」看原视频。
- `素材清单.csv`：每条一行，Excel / Numbers 能打开。
- `坏文件与重复副本.csv`。
- `<事件名>.fcpxml`：在 Final Cut Pro 里 **文件 › 导入 › XML…** 选它，选一个资源库，会新建一个事件：所有素材按拍摄日期排好，左侧关键词精选按「地点 / 日期 / 来源文件夹 / 场景 / 光线 / 景别 / 运镜 / 人物 / 风格 / 用途 / 技术问题 / 重复组」分进文件夹；3 分 = 个人收藏（绿条），0 分 = 拒绝；片段名 = 编号 + 一句话描述，备注里有地点和日期。FCP 只是链接原文件，**导入后原文件不要挪位置**，否则要重新链接。FCPXML 版本 1.9，2020 年以后的 FCP 都能导。

## 第 7 步（可选）：把素材整理进新文件夹

```
python3 <技能目录>/scripts/organize.py --work <工作文件夹> --dest <输出文件夹>/整理好的素材 [--mode copy|link]
```

按主场景分子文件夹，文件名 = 星级 + 编号 + 一句话描述 + (原文件名)；另有「★★★ 精选」「✕ 废片」「未分类」。`copy` 在同一块 APFS 硬盘上用克隆（`cp -c`，几乎不占空间），跨硬盘才真复制（先查空间够不够）；`link` 只放替身。原素材不动；重跑跳过已有文件。不用 FCP 的用户主要看这个。`build.py --no-fcpxml` 可以不生成 FCP 文件。

## 交给用户时说清楚

- 一共多少条、精选几条、废片几条、坏文件几个，抽查结果。
- 成品在哪（完整路径），先打开 `index.html` 看。
- 日期不可信或地点待定的有多少条，需要他补什么（行程表），补完只需要重跑第 6 步。
- AI 标签是第一遍粗分，描述可能有错；可以在网页里搜、在 FCP 里改关键词。

## 常见问题

- **联系表里的中文是方框**：系统缺中文字体（`common.py` 里有字体候选列表），装一个思源黑体/Noto Sans CJK 即可，不影响分类。
- **某条解不出画面**：在「坏文件与重复副本.csv」里标成「解不出画面」，多半是文件损坏或编码太新，用户可以用原相机/软件重新导出。
- **想加素材**：新素材放进同一个文件夹，从第 1 步重跑（已有编号不变，新素材接着编号）。`check.py` 会列出缺哪些编号、在哪几批；只把这几批重新派出去，输出写到新文件（如 `part_03b.jsonl`），同一编号以文件名排在后面的为准。
- **想换一套标签重新分**：改 `vocab.json` → 重跑 `make_brief.py` → 清空 `cls/` 后重新分类（先把旧的 `cls/` 改名留着）。
